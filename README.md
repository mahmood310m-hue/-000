# تطبيق مدرسة كوثر الأهلية المختلطة (Kauthar Private Mixed School)

تطبيق أندرويد بـ **Flutter** مع **Supabase** (مصادقة + PostgreSQL + تخزين صور).
الواجهة عربية بالكامل (RTL) بخط Cairo، وألوان نعناعية هادئة وبطاقات بيضاء مدورة.

## ما الذي يتضمنه المشروع
| المكوّن | المسار |
|---|---|
| كود التطبيق (Dart) | `lib/` |
| قاعدة البيانات + سياسات RLS + الدوال | `supabase/schema.sql` |
| بناء APK تلقائياً | `.github/workflows/build-apk.yml` |

مجلد `android/` **لا يُرفع إلى GitHub**؛ يُولَّد تلقائياً أثناء البناء (`flutter create`) مع إضافة صلاحية الإنترنت واسم التطبيق، فيبقى المستودع صغيراً وقابلاً للتحديث بسهولة.

## الميزات
- تسجيل دخول حقيقي (رقم هاتف + كلمة مرور) عبر Supabase Auth، مع إظهار/إخفاء كلمة المرور ورسائل خطأ وتسجيل خروج.
- ساعة إلكترونية في أعلى اليسار (تتحدث كل ثانية، اضغطها للتبديل بين ١٢/٢٤ ساعة) مع التاريخ.
- شريط أخبار يتحرك من اليسار إلى اليمين، يُدار من لوحة الإدارة، والضغط عليه يوقفه/يستأنفه.
- الصفحة الرئيسية: البطاقة الترحيبية + أربع بطاقات (الطلبة، المتفوقون، العام الدراسي، الإعلانات) تُحدَّث تلقائياً.
- الأقسام: المتفوقون (مرتبون بالمعدل)، الدرجات (حسب الصف + المعدل النهائي)، الحضور والغياب (مع تقرير)، الإعلانات (مع صور)، الطلبة (مع بحث).
- لوحة إدارة: الطلبة، المتفوقون، الدرجات، الحضور، الإعلانات، الشريط الإخباري، الصفوف، المواد، حسابات المستخدمين، صلاحيات المعلمين، ربط أولياء الأمور، إعدادات التطبيق (العام الدراسي، الشعار، نصوص الرئيسية، إخفاء الأقسام)، الإحصائيات والتقارير. كل حذف يمرّ بنافذة تأكيد.
- الأدوار: `super_admin` و`admin` و`teacher` و`student` و`parent`، مطبَّقة **في قاعدة البيانات عبر RLS** وليس في الواجهة فقط.

## الخطوات (مرة واحدة)

### ١) إنشاء مشروع Supabase
1. أنشئ مشروعاً في https://supabase.com
2. افتح **SQL Editor** والصق محتوى `supabase/schema.sql` كاملاً ثم **Run**.
3. من **Project Settings → API** انسخ `Project URL` و`anon public key`.
   لا تستخدم مفتاح `service_role` في أي مكان من التطبيق أو GitHub.

### ٢) تفعيل تسجيل الدخول
**الخيار أ — مزود الهاتف (الافتراضي):** من **Authentication → Providers** فعّل *Phone* وعطّل *Confirm phone*.
قد يطلب Supabase ضبط مزود رسائل SMS لتفعيل هذا المزود حتى لو لم تُرسَل رسائل فعلاً.

**الخيار ب — بدون SMS:** اضبط متغير GitHub `AUTH_MODE` على `email`. عندها يحوّل التطبيق رقم الهاتف داخلياً إلى بريد
`9647XXXXXXXXX@phone.kauthar.school` (فعّل مزود *Email* وعطّل *Confirm email*).
عند إنشاء المستخدم في لوحة Supabase استخدم هذا البريد وضع في `User Metadata`: `{"phone":"+9647XXXXXXXXX","full_name":"الاسم"}`.

صيغة الرقم: يقبل التطبيق `07701234567` أو `+9647701234567` (يُضاف رمز الدولة `964` تلقائياً، ويمكن تغييره بمتغير `COUNTRY_CODE`).

### ٣) إنشاء الحسابات
- من **Authentication → Users → Add user** أنشئ حساباً (هاتف + كلمة مرور، مع *Auto confirm*).
- يُنشأ له سجل في `profiles` تلقائياً بدور `student`.
- ارفع أول حساب إلى مدير أعلى **من SQL Editor فقط**:
```sql
update public.profiles set role = 'super_admin'
where phone in ('+9647XXXXXXXXX','9647XXXXXXXXX');
```
- بعد ذلك يغيّر المدير الأعلى أدوار بقية الحسابات من التطبيق (الإدارة ← حسابات المستخدمين).
  (إنشاء حسابات جديدة يتم من لوحة Supabase لأن ذلك يحتاج مفتاح خدمة لا يجوز وضعه في التطبيق.)

### ٤) رفع المشروع إلى GitHub
```bash
git init && git add . && git commit -m "Kauthar school app"
git branch -M main
git remote add origin https://github.com/<حسابك>/<المستودع>.git
git push -u origin main
```
في GitHub: **Settings → Secrets and variables → Actions**
- Secrets: `SUPABASE_URL` و`SUPABASE_ANON_KEY`
- Variables (اختياري): `COUNTRY_CODE` و`AUTH_MODE`

> مفتاح `anon` مصمَّم ليكون داخل التطبيق، وأمان البيانات يعتمد على سياسات RLS. لا تضع كلمات مرور أو مفاتيح سرية في الكود.

### ٥) بناء APK
يعمل البناء تلقائياً عند الرفع إلى `main`، أو يدوياً من **Actions → Build APK → Run workflow**.
بعد النجاح نزّل `kauthar-school-apk` من **Artifacts** وثبّته على الهاتف (اسمح بالتثبيت من مصادر غير معروفة).

> التوقيع الافتراضي (debug keys) كافٍ للتثبيت المباشر. للنشر على Google Play أضف توقيع إصدار خاصاً بك.

### ٦) البدء بالاستخدام
من لوحة الإدارة أضف بالترتيب: **الصفوف** ← **المواد** ← **الطلبة** ← الدرجات/الحضور/المتفوقين/الإعلانات.
لا توجد أي بيانات وهمية؛ التطبيق يعرض ما تُدخله فقط.

## التحديث لاحقاً
عدّل الكود وارفعه إلى `main` وسيُبنى APK جديد. ولتغييرات قاعدة البيانات أضف ملف SQL جديداً داخل `supabase/` ونفّذه في SQL Editor.

## ملاحظات أمنية
- لا يُسمح بتعديل الدرجات إلا لمن يملك الصلاحية (Admin أو معلم ممنوح) — يُفرض في RLS.
- الطالب يرى بياناته فقط، وولي الأمر يرى أبناءه المرتبطين فقط.
- قائمة المتفوقين تُقرأ عبر `honor_list` (اسم وصف ومعدل فقط) دون كشف بيانات الطلبة الشخصية.
- بوابة الإدارة تعيد التحقق بالهاتف وكلمة المرور ثم تسأل الخادم (`is_admin()`).
